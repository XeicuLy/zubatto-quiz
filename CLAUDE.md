# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project state

ズバッとクイズ (ズバクイ) is a real-time multiple-choice quiz app where players score on both correctness and answer speed. The pnpm workspace (`apps/*`, `packages/*`, `tools/*`) holds:

- `apps/api`: the API Worker (Hono) and one Durable Object per room ([backend.md](docs/architecture/backend.md)).
- `apps/web`: the SPA (TanStack Router) and the Worker that forwards `/api/*` ([frontend.md](docs/architecture/frontend.md)).
- `packages/protocol` (the WebSocket messages and the HTTP shapes) and `packages/scoring` (points and ranks), shared by both ([backend.md](docs/architecture/backend.md#メッセージの形)).
- `tools/docs-check`: tests that keep the documents in step with the repo ([operations.md](docs/architecture/operations.md#文書と-workflow-のテスト)).
- `tools/loadtest` (the O2 rehearsal bots), `tools/contract` (contract tests that check what a server sends against `ws.schema.json` and `openapi.json`, for this server and the Go one) and `e2e/` (one Playwright run through the whole game against a production-like build) ([testing.md](docs/architecture/testing.md)).

Before you design or implement anything, read the documents below. They are the source of truth:

- `docs/requirements/zubatto-quiz.md` is the requirements spec. Requirement IDs are `F*` (functional), `P*` (performance), `S*` (security), `A*` (availability), `SC*` (scalability), `M*` (maintainability), `C*` (cost) and `O*` (operations). ADRs and commits cite these IDs.
- `docs/adr/0001`–`0012` record the accepted architecture decisions. 0008 replaces ADR 0001's migration plan: production stays on Cloudflare, and the Go version is a separate practice environment on Cloud Run, checked by the contract tests; whether production ever switches is a later ADR. 0011 keeps the HTTP API as it is: the web calls it with `fetch` and protocol's zod, `openapi.json` is written from protocol's zod, and neither Hono RPC (`hc`) nor `@hono/zod-openapi` is used; its Consequences list when to revisit that. 0007 decides UI parts: shadcn/ui on Base UI (Radix's Dialog injects a `<style>` the CSP blocks on every open; checked on `e2e:serve` 2026-10-29), shadcn's token names (`background`/`foreground`, `primary`/`primary-foreground`, `ring`…) with the stage surface swapping the values, Digital Agency design system values as the reference for type, contrast and the focus ring, and the `@/*` alias in `apps/*` only (`packages/*` are read as source, so they stay relative). 0009 decides releases: release-please's release PR sets the version, tag and Release; production is tracked by the `production` Deployments and deployed only after a Required reviewers approval. 0010 replaces part of 0005 and 0009: `release: published` starts deploy.yaml on the tag's commit with target `all`, `v*` tags can be created only by the release-please App (tag ruleset), production allows `v*` tags, the production jobs merge into one so a run needs one approval, and `verify-ci` checks the tag's commit is on `main` and waits for its CI. The tag ruleset and production's `v*` policy are in the runbooks (#170). 0012 replaces 0009's release-please and 0010's `release: published` trigger: deploy.yaml runs only by `workflow_dispatch` with `bump` (auto / major / minor / patch) and no `target` (always migrations → API → web); `verify-ci` picks the version from the latest `v*` tag and stops before the approval when auto finds nothing to bump or the previous CHANGELOG PR is still open; after `deploy` succeeds, a `release` job (`environment: release`, App token, no dependency install) opens the CHANGELOG PR first and then creates the Release, which tags `github.sha` (so a half-done `release` leaves an open PR that stops the next dispatch; rerun the failed job). Merge the CHANGELOG PR by hand after its Release exists. Rolling back to a tag up to v1.3.0 uses that tag's deploy.yaml, whose `target` defaults to `web`: pick `all`. changelogen only writes the notes. Until #245 lands, the release-please flow still runs. Each ADR's "対応事項" list under Consequences is effectively the implementation checklist.
- `docs/architecture/` explains in Japanese how things work and where each rule is enforced: `backend.md` (the API Worker, the room DO, protocol and scoring), `frontend.md` (`apps/web`), `testing.md` (Workers tests, E2E, the load test and the contract tests) and `operations.md` (infra, rulesets, releases, deploys, logs and the docs-check tests). The promises below link to their sections; when you change a rule, update both.
- `plan.md` holds the original rough idea, including the frontend stack: React + TanStack Start as an SPA with `ssr: false`, TanStack Query, and zustand if needed. Where it conflicts with the requirements or ADRs, those win. TanStack Start was dropped for TanStack Router alone, because its SPA shell needs inline scripts that break `script-src 'self'` (ADR 0006). `memo.md` is a gitignored scratch file.

## Commands

```sh
make setup          # mise install (node/pnpm/uv/shellcheck pinned in .mise.toml) + pnpm install --frozen-lockfile
make check          # everything CI runs: fmt:check, lint, tsc, test
pnpm run fmt        # oxfmt (printWidth 120, single quotes, sorted imports/Tailwind classes/package.json)
pnpm run fmt:check
pnpm run lint       # oxlint --deny-warnings over the whole repo (.oxlintrc.json), then shellcheck .github/scripts/*.sh (pinned in .mise.toml)
pnpm run tsc        # root tsc --noEmit, then each package's own `tsc` script
pnpm run test       # vitest run; root vitest.config.ts bundles apps/*, packages/* and tools/* as projects
pnpm exec vitest run --project <name>   # one package; the project name is its vitest config `name`, else its package.json `name`, else its directory name
make e2e            # pnpm run e2e (Playwright, e2e/); first run needs `pnpm exec playwright install chromium`
pnpm run guide:shots   # retake /guide's screenshots against e2e:serve (e2e/guide-screenshots/, not in CI)
pnpm --filter @zubatto-quiz/web run storybook   # Storybook on port 6006; storybook:build writes apps/web/storybook-static/ (not published)
mkdir -p logs && pnpm -s run logs:api >> "logs/api-$(date +%Y%m%d-%H%M%S).json"   # O1 backup: wrangler tail --format json of zubakui-api (also logs:web); keep the files 7 days after the last entry (O1)
```

- A Claude Code PostToolUse hook runs `oxfmt` on every file after Edit/Write, so don't format by hand.
- `pnpm-workspace.yaml` sets `saveExact: true`, so `pnpm add` pins exact versions; a hand-written range in `package.json` fails `pnpm-exact-versions.test.ts`. pnpm 11+ reads only auth and registry settings from `.npmrc`, so don't put other settings there ([why](docs/architecture/operations.md#npm-の依存の更新)).
- CI (`.github/workflows/ci.yaml`) runs the same four checks plus `gh actions-lock --verify` (network, so not in `make check`) on every PR to `main` and every push to `main` in the `ci` job, and the Playwright E2E in the `e2e` job. `pr-title.yaml`'s `pr-title` job lints the PR title (also on `edited`, so it isn't in `ci.yaml`) and, on a push, the `main` commit message. The `main` repository ruleset requires all three (GitHub Actions only) and has no bypass actors, so not even admins can merge a failing PR. Keep those job names. `storybook.yaml`'s `storybook` job runs `storybook:build` on the same triggers but is not required, so a broken catalogue never blocks a production fix: keep it out of `main-ruleset.json`, with no secrets or token (`ci-workflow.test.ts`). A required check's workflow must run on both PRs to `main` and pushes to `main`, because `verify-ci` looks for it on the `main` commit; `main-ruleset.test.ts` checks this across `.github/workflows/`. `ci-workflow.test.ts` also fails any `run:` that embeds `github.event.*` or `github.head_ref` in `${{ }}`; pass such values through `env:`.
- Each package's `tsconfig.json` extends `tsconfig.base.json` and adds its own `types`/`lib`. A package with a `tsc` script is type-checked by the root `pnpm run tsc`.
- vitest 4 fails with "No projects were found" when no project glob matches, so `vitest.config.ts` leaves `projects` unset while `apps/`, `packages/` and `tools/` are empty. `@cloudflare/vitest-pool-workers` is deprecated and renamed to `@cloudflare/vitest-plugin`, which supports vitest 4 and 5 (checked 2026-10-11).
- oxlint rejects `dangerouslySetInnerHTML`, `innerHTML`-style DOM APIs (ADR 0004) and imports of test code (`test/`, `*.test.*`, `*.spec.*`) or Storybook (`*.stories.*`, `@storybook/*`, `storybook`) from production code. Test code, stories and `apps/web/.storybook/` may import production code.
- In `apps/web/src`, imports flow one way: `routes/` → `features/` → `shared/` → `api/`/`realtime/`, and `components/ui` reads only `lib/` and itself. No feature imports another; move what two features share into `shared/`. oxlint's `no-restricted-imports` overrides enforce it and `import/no-cycle` is on repo-wide. Each layer override repeats the global bans, so change them together; the test-code override stays last ([why](docs/architecture/frontend.md#全体の形)). `tools/docs-check/test/oxlint-layers.test.ts` checks the fences.
- Inside `apps/*`, import a parent folder's file as `@/…` (that app's `src/`), never `../`; oxlint's `import/no-relative-parent-imports` stops it in `apps/*/src/` except test code. `./` siblings and test helpers under `test/` stay relative, and `packages/*`/`tools/*` stay relative (ADR 0007). Define `@/*` only in tsconfig `paths`; Vite and vitest read it with `resolve.tsconfigPaths: true`, never `resolve.alias`, because web's Vite also builds the API Worker ([why](docs/architecture/frontend.md#全体の形)).
- oxlint's `jsx-a11y` plugin is on (its `correctness` rules, except `prefer-tag-over-role`: `<output>` and `<img>` don't fit a `role="status"` `<p>` or an inline `<svg role="img">`). Move initial focus with a ref and `useLayoutEffect`, never `autoFocus` (`no-autofocus`). A false positive gets `// oxlint-disable-next-line <rule>` with the reason on the line above (`autocomplete="nickname"`, an `alertdialog` catching a bubbled Esc).

## Commits

- Commitlint enforces Conventional Commits through a husky `commit-msg` hook. The type is in English and the subject is in plain-form Japanese, for example `docs: 1部屋の WebSocket 接続に100本の上限を設ける`.
- PRs are squash-merged only (ADR 0009), with the squash body blank, so **the PR title becomes the commit on `main` and its CHANGELOG line**. `pr-title.yaml` checks it with the same commitlint config. Only `feat`/`fix`/`perf` reach the CHANGELOG and bump the version; mark a breaking change with `!` in the title. Commits inside a PR are still split (code and docs apart) for review.
- Don't mention the target event or its deadline in commit messages.
- `.claude/settings.json` denies `git reset`, `git rebase` and `git rm`.

## Planned architecture (from the ADRs)

Production is all TypeScript on Cloudflare's free plan and stays there (ADR 0001, 0008). A Go version is built on Cloud Run with Terraform as a separate practice environment, and the web is pointed at it to compare (ADR 0008). Keep backend platform specifics out of anything the frontend depends on. In particular, the **WebSocket JSON message spec must be platform-independent and shared between frontend and backend**, so pointing the web at the Go server doesn't touch the frontend.

- **Backend** (`apps/api`, `packages/protocol`, `packages/scoring`): the reasons, file names and test helpers are in [docs/architecture/backend.md](docs/architecture/backend.md). Keep these promises:
  - [Shape](docs/architecture/backend.md#全体の形): one Hono Worker plus one Durable Object per room (Hibernation API + DO SQLite), the single source of truth. No polling or SSE. Every path is under `/api/` on one origin, with no CORS (ADR 0006). Don't deploy `apps/api` during an event.
  - [Question sets](docs/architecture/backend.md#問題セットと部屋を作る): every D1 access takes `owner_id`, and another host's set or room looks missing (404, 4404) (S1). Rooms use `newUniqueId()`, never `idFromName` (S3), and copy the set in one `transactionSync`; play never reads D1. Cookie routes that change state use `.use(csrf(), requireHost)`, `csrf()` first.
  - [WebSocket entry](docs/architecture/backend.md#websocket-の入口): check `Origin` before any cookie, never forward the browser's request to the DO (`roomRequest`), and register `wsRoutes` before `roomRoutes`. Never refuse a browser's WebSocket with an HTTP status: accept it and close with an app code (`refuseConnection`).
  - [Host auth](docs/architecture/backend.md#ホストの認証): check the allowlist in `user.validateUserInfo` (before any row is written; `account.create.before` would leave a `user` row) and again in `session.create.before`. `testUtils` goes only in the test-only auth. `/auth/*` keeps its `bodyLimit`, because Better Auth validates unbounded arrays before login.
  - [Progression](docs/architecture/backend.md#進行の操作): host commands only from host-role sockets, in protocol's `transition` order. `handleHostCommand` and `handleAnswer` call `closeAnsweringIfDue` first ([why](docs/architecture/backend.md#締切と採点)).
  - [S2](docs/architecture/backend.md#結果と送り直し): correct answers never leave the DO before the deadline. Outside `initialize`, only `scoreQuestion` and `results.ts` read `correct_index`. Results are never stored; they are rebuilt with a fixed number of queries (P4). Send only through `room/send.ts`: `broadcast` skips unverified sockets, and `answerProgress` goes only to hosts (`sendToHosts`).
  - [Players](docs/architecture/backend.md#回答者の参加とつなぎ直し): the secret goes only in the first WS message, never a URL or log; the DO keeps its SHA-256 and compares with `timingSafeEqual`, never `WHERE token_hash = ?`. `participantId` comes from the attachment, never the body, and a `null` attachment may send only `join`/`resume`. After an `await` (`hashToken`), re-check `OPEN` and the attachment.
  - [Concurrency](docs/architecture/backend.md#同時に起きる処理の約束): count against the cap before `acceptWebSocket` with no `await` in between (players 100 and hosts 5, counted apart). The `join` checks and insert are synchronous SQL. One answer per question is `UNIQUE` plus the accepting check in one `transactionSync`, with `ON CONFLICT … DO NOTHING`, never `INSERT OR IGNORE`.
  - [Messages](docs/architecture/backend.md#メッセージの形): decode with `decodeClientMessage` and send with `encodeServerMessage`. A field added to a server message gets a `.default()`. After a schema change, run `pnpm --filter @zubatto-quiz/protocol run schema` (`ws.schema.json` is the source of truth for the Go version). The web reads HTTP responses with protocol's schemas, never Hono RPC (`hc`), and `@hono/zod-openapi` stays out of the Worker (ADR 0011).
  - [D1](docs/architecture/backend.md#d1-のスキーマ) and [room SQLite](docs/architecture/backend.md#部屋の-do-の-sqlite): migrations come from `db:generate`, are never edited by hand and stay additive once deployed; never edit a deployed `ROOM_MIGRATIONS` version. Room SQL uses `ctx.storage.sql` (no drizzle) and binds every value with `?`.
  - [Scoring](docs/architecture/backend.md#採点の関数): points and ranks come only from `packages/scoring`. Change values only in `config.ts` (M2), and normalize each elapsed time once with `normalizeElapsedMs` (P2).
- **Operations** (ADR 0005, 0009, 0010): the reasons and the tests behind each setting are in [docs/architecture/operations.md](docs/architecture/operations.md); the procedures are the runbooks under `docs/runbooks/` (linked from README). Keep these promises:
  - [Infra](docs/architecture/operations.md#インフラの管理): `wrangler.jsonc` is the only IaC; Terraform is only for the Go practice environment, never production (ADR 0008). Secrets go in with `wrangler secret put --env=""`, never in a workflow or a `vars` entry. Anything config can't express goes in a runbook, and a change that affects one (a secret, a table, a command, a CI job name) updates it in the same change. `apps/api/.dev.vars.example` lists the `secrets.required` names with no values. `host_allowlist.github_user_id` is TEXT (`'12345'`).
  - [Rulesets](docs/architecture/operations.md#ルールセット): `main-ruleset.json` and `release-tag-ruleset.json` stay in the shape `gh api -X POST .../rulesets --input` takes and match GitHub. The required checks (`ci`, `e2e`, `pr-title`) are read from the ruleset, never copied into a workflow. Create the `v*` tag ruleset before letting production deploy `v*` tags.
  - [Releases](docs/architecture/operations.md#リリース): release-please runs with the App token, never `GITHUB_TOKEN`. Merges are squash-only. Never write `BEGIN_COMMIT_OVERRIDE` in a PR body's prose. Keep root `package.json`'s `"version"` right under `"name"`, and leave `CHANGELOG.md` and `.release-please-manifest.json` to release-please (oxfmt ignores both). Dry-run with release-please 17.6.0.
  - [Deploys](docs/architecture/operations.md#デプロイの-workflow): production deploys run only from `deploy.yaml`, never a local `wrangler deploy`. `deploy` stays the only job with `environment: production`, so a run needs one approval: don't split it, don't replace the reviewers with a gate job, and don't add `queue: max`. `verify-ci`'s `timeout-minutes` stays above `CI_WAIT_SECONDS`. When you change a job's `if` or `env.TARGET`, extend `targetOf`/`evaluateIf` in `deploy-workflow.test.ts`. Read what production runs from the step results ([deploy.md](docs/runbooks/deploy.md#デプロイのあとに確かめる)'s step 0), not the Deployments list. Don't merge the release PR during an event.
  - [verify-ci](docs/architecture/operations.md#verify-ci): catch a failed `gh api` with `if ! result=$(…)`, so one GitHub 5xx doesn't end the wait through `set -e`, and brace a variable followed by full-width text (`${result}）`).
  - [Action pins](docs/architecture/operations.md#action-の固定): `.github/workflows/actions.lock` pins every action and is generated, so never edit it by hand. Write `uses:` as a full version tag, with no SHA or version comment. After changing a `uses:` or adding a workflow, run `gh actions-lock` over the whole directory and read the lock's diff. `ci` runs `--verify`, never `--verify-local`, before `pnpm install`, with `GH_TOKEN` only on its two steps. `--verify` passes external reusable workflows and floating refs in the lock, so `ci-workflow.test.ts` stops those; don't remove that test. A failure from a network error gets a rerun ([how to read a failure](docs/architecture/operations.md#ci-で落ちたとき)).
  - [Dependabot](docs/architecture/operations.md#dependabot-での更新): it updates `uses:` and `actions.lock` in one PR and the npm dependencies in another, with no auto-merge; `.mise.toml` is updated by hand. Keep `commit-message.prefix` (`ci` for actions, `chore` for npm) with no `include: scope` (PR titles must pass commitlint), major updates out of the main group (`minor-and-patch` stays last, because a dependency joins the first group it matches), updates that need a hand fix in their own groups even for minor and patch (`cloudflare` for `wrangler`/`@cloudflare/*`, `oxc` for `oxlint`/`oxfmt`), so they don't block the rest, `cooldown`, and the `ignore` on the `@babel/core`, `@types/node` and `typescript` majors (remove `typescript`'s once 7.1 ships its API). Never add `minimumReleaseAge`, `minimumReleaseAgeExclude` or `trustLockfile` to `pnpm-workspace.yaml`; on `ERR_PNPM_MINIMUM_RELEASE_AGE_VIOLATION`, wait a day and rerun. `tools/docs-check/test/dependabot.test.ts` checks these. The `cloudflare` PR that bumps `wrangler` fails `tsc` until the branch regenerates `worker-configuration.d.ts` (`types` in `apps/api` and `apps/web`). Don't run `pnpm update -L` across the repo: it skips `ignore` and `cooldown`. Before merging, change its PR title's subject to Japanese; commitlint doesn't catch English.
  - [mise](docs/architecture/operations.md#mise-の版とキャッシュ): `actions.lock` doesn't pin the mise binary, so every `mise-action` sets the same `with.version`, raised by hand because Dependabot leaves it alone. `deploy` keeps `cache: false`, so tools that handle the Cloudflare token never come from a cache `ci` and `e2e` can write. `ci-workflow.test.ts` checks both.
  - [Logs](docs/architecture/operations.md#ログ): the app logs nothing of its own; anything added logs fixed keys only, never secrets, names or message bodies ([logs.md](docs/runbooks/logs.md#ログに残るもの残らないもの)). Save `logs:api`/`logs:web` with `pnpm -s` and `>>`, never `>`. `invocation_logs` stays on.
  - [Docs checks](docs/architecture/operations.md#文書と-workflow-のテスト): a document with relative links or `pnpm run` commands goes in `tools/docs-check/test/documents.ts`. Put each `pnpm run` command on its own line, because a full-width `）` right after a script name is read as part of it.
- **Frontend** (`apps/web`): the reasons, file names and test helpers are in [docs/architecture/frontend.md](docs/architecture/frontend.md). Keep these promises:
  - [XSS](docs/architecture/frontend.md#xss-を防ぐ): XSS hardening replaces HttpOnly here (the player secret is in localStorage). The CSP `script-src 'self'` is in `apps/web/public/_headers`; keep `apps/web/index.html` free of inline scripts, styles and event handlers, and load fonts from `@fontsource`. User input never becomes elements: no `innerHTML`-style APIs, and `question.text` is rendered as plain text (no Markdown, no `<br>` splitting), with `whitespace-pre-line` only to show its newlines.
  - [Colours](docs/architecture/frontend.md#色の役割) and [type](docs/architecture/frontend.md#文字と余白とフォーカス): use shadcn's role names (`bg-primary`…) and role sizes (`text-title`…), never `text-lg` or spacing named by size; Dela Gothic One only as `font-numeral` (projector numbers and ranks) and `font-logo`, everything else M PLUS 1 with `font-bold` for headings; the vw `text-stage-*` tokens are for the projector only. Which token goes where is listed in [docs/design/README.md](docs/design/README.md#トークンの一覧と使い分け); its mock keeps the old names (`stage`, `backstage`, `on-*`), so never copy classes from it. Text needs 4.5:1 and non-text borders 3:1: add each new colour pair to `test/contrast.test.ts`, and e2e's axe checks `color-contrast` on the real screens. A new `@theme` name goes into `createCn` in `src/lib/tailwind.ts`, and `cn` comes from `@/lib/tailwind` ([why](docs/architecture/frontend.md#shadcn-と-cn)).
  - [UI parts](docs/architecture/frontend.md#ui-の部品): screens use the parts in `src/components/ui/` and never import `@base-ui/*` (oxlint stops it). Build a part from `shadcn add <name> --view` by hand, minus its focus classes and `transition-all`; pick colours by role only, never by surface. A `<Link>` that looks like a button takes `buttonVariants()`, not `render`.
  - [Storybook](docs/architecture/frontend.md#storybook): put `<part>.stories.tsx` next to its part (CSF 3, `satisfies Meta<typeof Part>`); `preview.tsx` adds `autodocs` to all. Storybook reads `.storybook/vite.config.ts` (`react()`, `reactCompiler()`, `tailwindcss()`, `tsconfigPaths`), never `vite.config.ts`, so no cloudflare or tanstackRouter. Show the dark surface with `globals: { surface: 'stage' }`, never a `.stage` wrapper inside a story. `styles.css`'s `@source not` keeps stories and `.storybook` out of the production CSS, and `.storybook/preview.css` adds them back as file globs (a folder doesn't). Pick the size with `globals: { viewport: { value: 'mobile' | 'projector' } }` (390×844, 1920×1080, from `preview.tsx`), and pass fixed protocol-shaped values, never computed ranks or times. No play functions, addon-vitest or addon-a11y; `test/stories.test.tsx` renders every story once. Its glob lives in `test/story-files.ts`, written without a type argument: vitest 5's `fsModuleCache` keeps a stale file list for `import.meta.glob<T>(`, and `story-files.test.ts` compares the glob with the disk.
  - [Realtime](docs/architecture/frontend.md#部屋の-websocket): only `src/realtime/` touches the room WebSocket, and every message goes through protocol's `serverMessageSchema`. Reset the backoff `attempt` only on `joined`/`resumed`/`hostReady`, never on `open`.
  - [Connections](docs/architecture/frontend.md#接続を開く場所): open the room socket from routing (`loader`, `onEnter`/`onLeave`) and user actions, never from `useEffect`. One `zustand/vanilla` store per room; components only render the stores.
  - [Players](docs/architecture/frontend.md#回答者の参加): save the secret before connecting, and clear it only on the closes `rejectionOf` picks.
  - [Results](docs/architecture/frontend.md#結果の画面): ranks, ties, points and times come only from the DO's messages; seconds use scoring's `formatSeconds`. Write per-`variant` class maps in full (Tailwind reads literal strings), and `mobile` uses no `md:` classes.
  - [Host focus](docs/architecture/frontend.md#ホストの進行とフォーカス): after a host command, focus the new stage's heading through `settleFocus`, never the primary button (a second Enter would skip ①). Confirm in place with `ConfirmDialog` (`role="alertdialog"`, not modal; `useConfirm` returns focus to a replaced opener), never `window.confirm` or `AlertDialog`. An element focused only by script uses `focus-target`.
  - [Live regions](docs/architecture/frontend.md#読み上げ): announce with `useAnnouncement`; a screen that appears together with its text never gets `role="status"`.
  - [Guide](docs/architecture/frontend.md#使い方のページ): `/guide`'s steps live only in `features/guide/guide-steps.ts` (plain data, also read by the capture script and node tests). Load its images with `import.meta.glob`, never a `new URL()` template: vitest's `fsModuleCache` keeps a stale file list for the latter. After changing a screen the guide shows, rerun `guide:shots` and commit the PNGs in the same change ([how](docs/architecture/testing.md#使い方の画像を撮り直す)). No SSG: the pages are noindex.
  - [Titles](docs/architecture/frontend.md#ページタイトル): every route sets `head: () => pageTitle('<画面名>')`; never put a room ID, player name or set name in a title (S3).
  - [Host auth](docs/architecture/frontend.md#ホストのログイン): only `src/api/auth-client.ts` imports Better Auth. Host-only routes use `requireHost` in `beforeLoad`, which never trusts the cached session; logout calls `queryClient.clear()`. Use `queryClient.query(options)`, not the deprecated `fetchQuery`/`prefetchQuery`/`ensureQueryData`.
  - [Editor](docs/architecture/frontend.md#問題セットの編集): every edit goes through the pure `editorReducer`; `validateDraft` only maps protocol's `questionSetSchema` issues and holds no rules of its own.
  - [Sound](docs/architecture/frontend.md#音): play cues from `onMessage` in `host-room`/`player-room`, never from a component effect.
  - [Layout](docs/architecture/frontend.md#レイアウトの落とし穴): use `grid-cols-1` for stacked lists and `min-w-0` on a flex box that holds a `w-full` message, or the screen overflows at 390 px.
  - [Build](docs/architecture/frontend.md#全体の形): commit `src/routeTree.gen.ts`. Tests that read files run in node under `test/`. After changing `apps/web/wrangler.jsonc` or `src/server.ts`, rerun `pnpm --filter @zubatto-quiz/web run types`. React Compiler runs through Babel from `reactCompiler()` in `apps/web/react-compiler.ts`, right after `react()` in both `vite.config.ts` and `vitest.config.ts`. Keep `@babel/core` on 7.x: on 8.x the compiler silently skips components with default-valued props. Don't write `useMemo`, `useCallback` or `memo` by hand; where not recalculating matters, a test counts the calls (`JoinQrCode.test.tsx`).
  - [Tests](docs/architecture/frontend.md#テストの道具): route tests pass `FakeRoomServer.createSocket` to `createAppRouter`; tests of routes that read the session call `stubFakeApi` first; with fake timers, advance in small `act` steps.
  - [Browser check](docs/architecture/frontend.md#画面を実際に確かめる): after a screen change passes its tests, check it in the real app with the Playwright MCP, at 390×844 for player screens. The quickest host login: run `pnpm --filter @zubatto-quiz/web run e2e:serve` (port 4173, no HMR), then `fetch('/api/e2e/login', { method: 'POST' })` and `page.context().addCookies(cookies)`. Screenshots go under `.playwright-mcp/`.
- **Testing** (`apps/api` on the Workers runtime, `e2e/`, `tools/loadtest`, `tools/contract`): the helpers and the reasons are in [docs/architecture/testing.md](docs/architecture/testing.md). Keep these promises:
  - [Workers tests](docs/architecture/testing.md#workers-のテスト): `@cloudflare/vitest-plugin` runs DOs and D1 locally; use `evictDurableObject` for hibernation and restarts. Import `env` and `exports` from `cloudflare:workers`, and only test helpers (`runInDurableObject`…) from `cloudflare:test`. Never pass a DO stub's RPC promise straight to `expect(...).rejects`; wrap it (`settle`). Keep the Workers types (`src/`, tests) apart from the node types (`vitest.config.ts`). After changing `wrangler.jsonc`, run `pnpm --filter @zubatto-quiz/api run types`. Write invisible characters as escapes (`'\u200D'`, `'\u3000'`); the Write tool turns a `\u` escape into the character, so write such files from a script or check them afterwards.
  - [HTTP and WebSocket tests](docs/architecture/testing.md#http-と-websocket-のテストの道具): use `test/host-request.ts` (`resetHosts` in `beforeEach`) and `test/room-socket.ts` rather than hand-built requests and sockets. Don't fake `Date` in `close-question.test.ts`, which measures P4.
  - [Test login](docs/architecture/testing.md#テスト専用のログイン): Better Auth's `testUtils` goes only in the test-only auth instance. Never ship a test-login endpoint in the production entry, even one gated by a runtime env flag: `/api/e2e/login` lives only in `test/e2e-entry.ts`, and the `api-bundle` project checks the production bundle lacks it.
  - [Swagger UI](docs/architecture/testing.md#swagger-ui-で-http-api-を試す): `/api/docs` follows the same rule, because it loads scripts from a CDN: `@hono/swagger-ui` stays in `devDependencies`, imported only by `test/e2e-entry.ts`, and `api-bundle` checks both bundles for its path. It serves the committed `openapi.json` (protocol's `./openapi.json` export), never one rebuilt from zod, and pins the Swagger UI `version`, which Dependabot doesn't raise.
  - [E2E](docs/architecture/testing.md#通しの-e2e): run against `vite build` + `vite preview` (`e2e:serve`), never `vite dev`, because only they apply `_headers` (the CSP). Pass `CLOUDFLARE_ENV=e2e` to the build only. Give each actor its own `browser.newContext()`. Always run `vite build` right before a `wrangler deploy` of the web Worker, because an E2E build rewrites `.wrangler/deploy/config.json`. Each ADR's Consequences section lists the security and concurrency cases that must have automated tests.
  - [Load test](docs/architecture/testing.md#o2-のリハーサル用のボット): the host cookie comes only from `ZUBAKUI_HOST_COOKIE`, never an argument; bot secrets stay in memory, and logs name rooms `部屋1`…, never by ID (S3). Take counts from the dashboard, not `wrangler tail`, which samples under load.
  - [Contract tests](docs/architecture/testing.md#契約テスト): read only the exported `ws.schema.json` and `openapi.json`, with ajv (plus ajv-formats); never import protocol's TypeScript or zod, or zod's drift goes unseen. Scenarios that need a server run only when `CONTRACT_ORIGIN` is set, so `make check` stays offline.

## Writing docs and ADRs

- Docs are written in plain, jargon-light Japanese. Match the existing tone, for example "確かめる" rather than "検証する".
- ADRs use the MADR format at `docs/adr/NNNN-<slug>.md`. The title is the decision itself, and the sections are Status / Context / Decision Drivers / Considered Options / Decision Outcome / Consequences. They are usually authored with the `tech-adr:adr-writer` skill.
- Decision drivers are numbered `DD1`, `DD2`, and so on. ADR 0001 predates this and uses `D1`. Option IDs must not reuse requirement prefixes (`F`/`P`/`S`/`A`/`SC`/`M`/`C`/`O`).
- When a decision changes a requirement, update `docs/requirements/zubatto-quiz.md` in the same change. Past commits show this pattern.
- Check service limits, pricing and API behavior against current docs (context7 MCP first) and state the date checked. The ADRs depend heavily on free-tier numbers.
