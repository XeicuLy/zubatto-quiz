# デザインモック

ズバクイの主要な4画面の見た目を、静的な HTML と Tailwind CSS v4 で先に決めたもの。画面の実装（T24〜T32）は、このモックを見本にして作った。

このフォルダのモックは、T24 までの検討の記録として残している。実装のあとは直していない。

- 今の色・文字・間隔などのトークンの正は `apps/web/src/styles.css`。トークンを変えるときは styles.css を直し、`mock/theme.css` は直さない
- 今の画面の正は `apps/web/src/` の実装。モックにない画面や部品は、[モックと今の画面の違い](#モックと今の画面の違い)にまとめた
- [ADR 0007](../adr/0007-ui-components-approach.md) で、色トークンの名前を shadcn/ui の名前（`background`・`foreground` など）に変えると決めた。変えたあとは、モックのクラス名（`bg-stage` など）も styles.css と合わなくなる

このファイルの「決めたこと」「順位の見せ方」「1問の流れ」は、今の画面でも守っている決まり。

## 見方

```sh
make setup              # 初回だけ
pnpm run mock:build     # mock/dist/mock.css を作る
open docs/design/mock/player.html
```

編集しながら見るときは、`mock:build` の代わりに、別のターミナルで次を動かしたままにする。保存のたびに `mock/dist/mock.css` を作り直す。

```sh
pnpm run mock:watch
```

- HTML はブラウザで直接開ける（`file://` のままでよい）。フォントは Google Fonts から読み込むので、ネットにつながっている必要がある
- 1つの HTML に、画面の状態をいくつも入れてある。画面の上の「モックの状態」から選ぶか、URL の末尾に `#answer-3` のように状態の id を付ける
- 画面の幅を変えると、本番と同じように並びが変わる。投影は 16:9（1600×900 など）、スマホは縦向き（390×844 など）で確かめる

## 1問の流れ

締切のあとは、ホストが押すたびに1段ずつ進む。毎問出すのは ① と ② だけにし、③ はホストが出したいときに出す。毎問 ③ まで出すと、10問で30回押すことになり、進行が間延びするため。

| 段階                       | いつ                                       | 進行画面（投影）                                            | 回答者画面（スマホ）                   | モック                                                 |
| -------------------------- | ------------------------------------------ | ----------------------------------------------------------- | -------------------------------------- | ------------------------------------------------------ |
| 出題                       | ホストが「第N問を出す」を押す              | 問題文だけ                                                  | 問題文だけ                             | `host.html#question`・`player.html#question`           |
| 受付中                     | ホストが「受付を始める」を押す             | 選択肢・残り時間・回答数                                    | 選択肢（回答すると回答済み）           | `host.html#accepting`・`player.html#answer-4`          |
| ① 正解と回答の分布         | 締切（時間切れか、ホストが締め切る）       | 正解と、選択肢ごとの人数                                    | ○×と得点、自分の位置                   | `host.html#reveal`・`player.html#result-*`             |
| ② 最速正解の発表           | ホストが「最速正解を発表する」を押す       | 最速の3人と秒数、正解した人数、この問題で一番順位を上げた人 | ① の画面に最速正解者が出る             | `host.html#fastest`・`ranking.html#fastest`            |
| ③ 途中経過（なくてもよい） | ホストが「途中経過を出す」を押したときだけ | 上位10人                                                    | 上位10人（自分が入っていれば強調する） | `host.html#standings`・`ranking.html#question-ranking` |
| 最終ランキング             | 最後の問題のあと                           | 優勝者と全員の順位                                          | 同じ                                   | `host.html#final`・`ranking.html#final`                |

## 順位の見せ方

自分の位置はやんわり分かるけれど、トップが遠すぎるとは感じさせない。テレビのクイズ番組の手を組み合わせる。

- 回答者画面では、順位よりも「次の目標」を見せる
  - 1〜3位のときだけ、順位の数字を出す（上の人には守る楽しさがある）
  - それ以外は順位の数字を出さず、「1つ上の人まで あと 224点」を出す。「8位まで」と書くと自分が9位だと分かってしまうので、順位の数字は使わない
  - 1位のときは、2位との差を出す
- 矢印（▲5）は、順位が上がったときだけ出す。下がったときは何も出さない
- トップとの差と一緒に、「残り7問で、最大 8,400点 取れます」を出し、逆転できると数字で分かるようにする
- ② の「この問題で一番順位を上げた人」は、上げた幅だけを出し、順位の数字は出さない。速さが苦手な人にも見せ場ができる。順位の変化がない第1問では出さない
- 最後の2問は順位を伏せる。③ は出せず、② の「一番順位を上げた人」と、回答者画面の自分の位置も出さない。最終ランキングまで引っ張る

これらは要件定義書の F14・F15 に書いた。「1つ上の人との差」「一番順位を上げた人」「残りで取れる最大の点」は、締切の集計（T23）で packages/scoring の関数を使って出す。「一番順位を上げた人」は、前の問題の締切までに入室した人だけで前の順位を作って比べる。途中で入った人を、順位を上げた人には選ばない。メッセージでの渡し方は、メッセージ仕様（`packages/protocol` の `myResult` の `position` と `fastest`）で決めた。1〜3位だけが順位の数字を持ち、4位以下と最後の2問の位置は、順位の数字を持たない形にしてある。問題が2問以下のときは、どの問題も「最後の2問」に入るので、③ は出せない（T21）。② の「一番順位を上げた人」と自分の位置も、③ と同じ決まりで、どの問題でも伏せる（T23）。順位は最終ランキングで初めて分かる。

## 決めたこと

### 見た目の方向

クイズ番組のスタジオを下敷きにする。会場で一瞬で読めることを一番に考える。

- 進行画面と回答者画面の面は、スタジオのセットの深い青（`stage`）。真っ黒にはせず、投影しても沈まない色にする
- 選択肢は早押しパネルの4色（赤・青・緑・黄）。色だけで見分けられない人もいるので、必ず大きな番号と一緒に出す。黄色のパネルだけは、文字を暗い色（`on-choice-4`）にする
- 目立つ色（`spotlight` のピンク）は、② 最速正解の発表と優勝者にだけ使う。ほかの場所で使うと、見せ場が埋もれる
- 管理画面は明るい「楽屋」の面（`backstage`）。本番の前に落ち着いて問題を作る場所なので、道具らしくする
- 見出しと数字は Dela Gothic One、本文は M PLUS 1
- 動きは最速正解者と優勝の発表の1か所だけにする（`animate-spotlight-in`）。`motion-safe:` を付け、動きを減らす設定の人には出さない

### 画面の大きさ

- 進行画面とランキングは、画面いっぱいに出す。文字と余白は `text-question`・`p-stage` など、画面の幅（`vw`）に合わせて伸びるトークンを使う。PC からの投影とホストのスマホの両方で読める
- 回答者画面は、PC で開いても `max-w-md` の列に収める。文字の大きさは固定にし、`vw` で伸びるトークンは使わない
- 進行画面は `md` 以上で横に並べ（投影）、それより狭いと縦に積む（スマホ）

### 選択肢

- 回答者画面の選択肢は、縦に積んだ全幅のボタンにする。残りの高さを等分するので、2・3・4択のどれでも形が崩れない
- 出題（読み上げ）のあいだは問題文だけを出し、受付を始めた瞬間に選択肢を出す。P2 の「選択肢が表示された瞬間から計る」に合わせるため
- 問題文と選択肢には `text-phrase`（`word-break: auto-phrase`）を付け、日本語を文節で改行する

### 名前の出し方

回答者の名前は、`innerHTML` 系の API を使わず文字として描画する（ADR 0004）。はみ出し方は、場所によって2つを使い分ける。

| ユーティリティ | 使う場所                                                       | 出し方                                    |
| -------------- | -------------------------------------------------------------- | ----------------------------------------- |
| `name-clip`    | ランキング、回答の一覧、ヘッダーなど、行の高さをそろえたい場所 | 1行で省略する。`title` 属性で全文を見せる |
| `name-wrap`    | 参加者の一覧、自分の名前、最速正解者など、全部見せたい場所     | 折り返して全部見せる                      |

見本には、30文字ほどの長い名前、英字だけの長い名前、絵文字（家族の絵文字のように、いくつかの文字が合わさったものを含む）を入れてある。名前の長さの上限は、メッセージ仕様（`packages/protocol`）で32文字に決めた。前後の空白を除いてから数え、絵文字も1つを1文字と数える（コードポイントで数えるので、家族の絵文字のように合わさったものは、いくつかの文字になる）。見本の英字だけの長い名前も、ちょうど32文字で入る。

## T24 での移し方

T24 で、次のように本番へ移した。トークンの正本は `apps/web/src/styles.css` になったので、トークンを変えるときは styles.css を直す。

1. `mock/theme.css` の中身を、`apps/web/src/styles.css` の `@import 'tailwindcss';` の後ろへそのまま移した。`mock/mock.css` の中身（状態の切り替え）は移していない
2. `.oxfmtrc.json` の `sortTailwindcss.stylesheet` を `apps/web/src/styles.css` に向け直した。自前のトークン（`bg-stage` など）のクラスを正しい順に並べるのに使っている
3. フォントは Google Fonts ではなく、`@fontsource` から入れて同じオリジンから配る。CSP の `font-src`・`style-src` を `'self'` のままにできる。モックは今も Google Fonts から読み込む
4. モックが要らなくなったら、`@tailwindcss/cli` と `mock:build`・`mock:watch` を消す

## 確かめ方

モックを作ったときは、テストの仕組みと CI はまだなかった。このモックは、Playwright で全部の状態を 16:9（1600×900）とスマホ（390×844）で撮り、次のことを目で確かめた。

- どの状態も、1つだけ表示される
- 横にはみ出さない
- 2・3・4択のどれでも、回答者画面が崩れない
- 長い名前と絵文字の名前が、`name-clip`・`name-wrap` の決めたとおりに出る

今の画面は、`apps/web` の画面のテスト（vitest）と、`e2e/` の Playwright（axe によるアクセシビリティのチェックを含む）で確かめている。
