# ズバッとクイズ（ズバクイ） 要件定義書

## 概要

- **解決する課題**: 忘年会などのイベントで、参加者全員がその場で同時に遊べる出し物がほしい。内輪ネタのクイズは正解が1つに偏りやすく、正答率だけでは順位に差がつかない
- **対象ユーザー**:
  - **ホスト（出題者）**: 問題を用意し、部屋を作って URL を共有し、クイズを進行する人。基本は進行役だが、同じ URL から回答者として参加することもできる。開発者本人のほか、知り合いもホストになる。ホストは GitHub アカウントでログインし、開発者が許可リストに入れた人だけがホストになれる
  - **回答者**: URL から部屋に入り、名前を入力して参加するイベント参加者（1部屋20名前後を想定）
- **利用シーン**:
  - イベント会場で、ホストの進行に合わせて全員が同時に回答する。回答者は会員登録をしない
  - ホストの PC かスマホを進行画面にする。スクリーンがあれば投影し、なくても各自のスマホだけで遊べる
  - 最初の本番は2026年12月の忘年会。その後も別のイベントや別の問題セットで繰り返し使う
- **参考にした類似プロダクト・事例**: テレビ番組「オールスター感謝祭」のクイズ形式（問題の読み上げ後に回答し、正解の速さを競う。最速の正解者と秒数を区切りごとに発表する）

## ゴール

2〜4択のクイズで、正解したかどうかに加えて回答の速さも点数にし、内輪ネタで答えが偏っても順位に差がつくリアルタイムクイズを実現する。2026年12月の忘年会で20名前後が最後まで問題なく遊べ、その後も別のイベントで繰り返し使える状態にする。

## スコアの計算

F11・F12・F15・M2 の式と初期値。式はコードで決め、数は設定値にする。配点を変えるときは、設定値だけを変える（M2）。

### 設定値

| 名前                  | 初期値 | 意味                                                                   |
| --------------------- | ------ | ---------------------------------------------------------------------- |
| `basePoints`          | 500    | 正解したときの基本点                                                   |
| `maxSpeedPoints`      | 500    | 速さによる点の上限。経過時間が0秒のときの点                            |
| `quickBonus.withinMs` | 1000   | F12 の早押しボーナスをもらえる経過時間（ミリ秒）。この値ちょうども含む |
| `quickBonus.points`   | 200    | F12 の早押しボーナスの点                                               |

`quickBonus` は F12 を作るとき（SHOULD）に設定へ足す。それまでは設定に入れず、ボーナスは0点として計算する。

次のものは設定値にしない。変えるときは式（コード）を変える。

- 経過時間を0.01秒単位に切り捨てること（P2 で決めている）
- 速さの点を、残った時間の割合で直線的に減らすこと
- ボーナスの条件が「以内」（ちょうどを含む）であること

### 式

1. 経過時間 `elapsedMs` は、端末で計ったミリ秒の値を、0から制限時間 `limitMs`（F9）のあいだに収め、10ミリ秒単位に切り捨てる。表示・得点・ボーナス・最速正解者（F14）のどれにも、この値を使う
2. 不正解と未回答は0点
3. 正解は、次の3つの合計
   - 基本点: `basePoints`
   - 速さの点: `Math.floor((maxSpeedPoints * (limitMs - elapsedMs)) / limitMs)`。制限時間のうち残った時間の割合に比例し、端数は切り捨てる
   - ボーナス: `elapsedMs <= quickBonus.withinMs` なら `quickBonus.points`、そうでなければ0
4. 1問で取れる最大の点は `basePoints + maxSpeedPoints + quickBonus.points` で、制限時間によらない。初期値では1,000点、ボーナスを足したあとは1,200点。回答者画面の「残りの問題で取れる最大の点」（F15）は、残りの問題数 × この点

速さの点は、掛けてから割る。`maxSpeedPoints * (1 - elapsedMs / limitMs)` のように先に割ると、小数の誤差で1点ずれることがある（制限5秒・0.35秒では、465点のはずが464点になる）。

### 同点のとき

合計点が同じ人は、同じ順位にする（1位・2位・2位・4位のように数える）。回答時間や正解数では比べない。速さはもう点に入っているため。

同じ順位の人は、入室した順に並べる。表示するたびに並びが入れ替わらないようにするため。途中経過（③）と最終ランキングの両方で、この決め方を使う。

### 20名・10問の例

内輪ネタで正解が偏った場合を考える。制限時間はすべて10秒。

| 回答者  | 人数 | 毎問の回答時間                                        | 正解                                                                                    |
| ------- | ---- | ----------------------------------------------------- | --------------------------------------------------------------------------------------- |
| P1〜P18 | 18   | Pn は 1.50 + 0.30 × n 秒（P1 は1.80秒、P18 は6.90秒） | 1問だけ間違えて9問正解。P1 と P11 は第1問、P2 と P12 は第2問、…、P10 は第10問を間違える |
| 物知り  | 1    | 3.00秒                                                | 10問正解                                                                                |
| 勝負師  | 1    | 0.80秒（選択肢をよく読まずに押す）                    | 第3問と第7問を間違えて8問正解                                                           |

どの問題も17〜19人が正解する。正解数だけで順位を付けると、18人が9問正解で2位に並んでしまう。

速さの点を入れると、20人全員の点が違い、同点はない。Pn は毎問 925 − 15 × n 点を9問で取るので、合計は 8,325 − 135 × n 点になり、となりの人と135点ずつ差がつく。

| 順位 | 回答者 | 合計点 | ボーナスを足したあとの順位 | ボーナスを足したあとの合計点 |
| ---- | ------ | ------ | -------------------------- | ---------------------------- |
| 1    | 物知り | 8,500  | 2                          | 8,500                        |
| 2    | P1     | 8,190  | 3                          | 8,190                        |
| 3    | P2     | 8,055  | 4                          | 8,055                        |
| 4    | P3     | 7,920  | 5                          | 7,920                        |
| 5    | P4     | 7,785  | 6                          | 7,785                        |
| 6    | 勝負師 | 7,680  | 1                          | 9,280                        |
| 7    | P5     | 7,650  | 7                          | 7,650                        |
| …    | …      | …      | …                          | …                            |
| 20   | P18    | 5,895  | 20                         | 5,895                        |

ボーナスを足すと、1秒以内に正解した勝負師だけが、1問ごとに200点を足される（8問 × 1,160点 = 9,280点）。勝負師は2問を落としても、10問とも正解した物知りを抜いて1位になる。リスクを取った人が報われる。

ボーナスは、トップを追いかける側が1問で縮められる差も広げる。3秒で正解し続けるトップ（毎問850点）を、0.50秒で正解して追いかけるとき、1問で縮められる差は次のとおり。

- ボーナスなし: 975 − 850 = 125点。最後の3問で追いつけるのは、375点差まで
- ボーナスあり: 1,175 − 850 = 325点。最後の3問で追いつけるのは、975点差まで

逆転できる差が広がるので、1人が独走しにくくなる。

## 非機能要件

### パフォーマンス

- **P1**: ホストの出題・受付開始・締切の操作がサーバーに届いてから、接続中の全回答者の画面に反映されるまで1秒以内であること（会場の Wi-Fi やモバイル回線を想定）。切れていた回答者がつなぎ直したあとの扱いは A1・F19 で決める
- **P2**: 回答時間は、各自の端末に選択肢が表示された瞬間から回答を押すまでを0.01秒単位で計って表示すること。通信の速さによる不公平をなくすためで、端末側でごまかされる余地は身内の利用なので受け入れる。計った値は0.01秒単位に切り捨て、表示・得点・早押しボーナス・最速正解者の判定のすべてに同じ値を使う
- **P3**: 1部屋の上限である50名（SC1）が締切直前に一斉に回答しても、回答を取りこぼさないこと
- **P4**: 締切から、正解発表・最速正解者・ランキングを出せるようになるまで2秒以内であること（実際に出すのは、ホストの操作で1段ずつ）

### セキュリティ

- **S1**: ホスト以外は管理画面を開けず、進行操作もできないこと。ホストが複数いる場合も、各ホストが操作できるのは自分の問題セットと部屋だけであること
- **S2**: 正解は締切まで回答者の端末に送らないこと（開発者ツールを使っても見えない）
- **S3**: 部屋の URL は推測できない形にし、URL を知らない人は参加できないこと
- **S4**: 1人が1問に回答できるのは1回だけで、それをサーバー側でも確認すること。他人のふりをして回答できないこと
- **S5**: 回答者について扱う個人情報は、自分で入力した名前だけにすること

### 可用性

- **A1**: 本番の時間帯（約1〜2時間）に途中で止まらないこと。接続が切れた場合も、自動で再接続してゲームを続けられること。常に動いている保証（稼働率の目標）は求めない
- **A2**: サーバーがしばらく使われず止まっていた場合、入室時の待ち時間（コールドスタート）は許容する。入室後は、ホストの最初の進行操作から P1 を満たすこと
- **A3**: 障害が起きても、締切まで終わった問題の得点は失われないこと。復旧したら、障害が起きた問題からやり直せること

### スケーラビリティ

- **SC1**: 1部屋に最大50名まで参加できること
- **SC2**: 最大5部屋を同時に開いても、どの部屋でも P1〜P4 を満たすこと
- **SC3**: 表示は日本語のみとする

### 保守性・拡張性

- **M1**: CI で lint・型チェック・テストが通らないと main にマージできないこと
- **M2**: スコア計算（速さによる点数・早押しボーナス）は自動テストで確認し、配点を変えるときは設定値を変えるだけで済むこと（式と設定値は「スコアの計算」に書く）
- **M3**: README に開発環境の作り方を書き、コントリビュートを受け付けるのは知り合いだけであることも明記すること

### コスト

- **C1**: 基本は無料枠の中で動かすこと。ただし、すぐ止められるなら月500円程度までの課金は許す
- **C2**: 無料枠に収めることよりも、P1〜P4・A1〜A3 などの重要な要件を優先すること
- **C3**: 起動しているだけで料金がかかる常時起動のサーバーは使わないこと
- **C4**: 課金が起きうる構成（有料プランなど）にするときは、予算アラートを設定すること。無料プランでは、上限を超えたら課金されずに止まることを受け入れ、使用量は本番の前後にダッシュボードで確かめること。どちらの場合も、すぐ止められる手順を用意しておくこと

### 運用・監視

- **O1**: 本番中と本番後に、エラーのログを確認できること（少なくとも7日間は残す）
- **O2**: 本番の前に、1人で20名分の同時参加を再現してリハーサルできる仕組みがあること
- **O3**: 運用するのは開発者本人だけとし、夜間の通知などは不要とする

## スコープ外

- 回答者の会員登録・ログイン
- ホストを管理する画面（ホストの追加・削除は、開発者がコマンドで行う）
- 一度確定した回答の変更
- 端末を替えた回答者の、名前と得点の引き継ぎ（新しい回答者として、別の名前で入り直す）
- 同じ人が別のブラウザで、別の回答者としてもう一度参加することの防止
- 日本語以外の表示（多言語対応）
- 稼働率の目標値の設定・保証
- 夜間・休日の障害通知
- 知り合い以外からのコントリビュートの受け付け（不特定多数に向けた OSS としての運用）
