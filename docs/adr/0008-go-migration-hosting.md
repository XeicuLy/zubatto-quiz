# 本番の API は Cloudflare に残し、Go 版は Cloud Run の練習用の環境で作って確かめる

## Status

proposed

イベントのあとに見直し、accepted にする。

## Context

ADR 0001 は、イベントのあとでバックエンドを Go + Cloud Run + Terraform に置き換えると決め、そのときに max-instances を超えたときの同期、60分ごとの再接続、課金の自動停止を別の ADR で検討するとしていた。この ADR がそれにあたる。

調べると、Cloud Run を1台（max-instances 1）にしても部屋が2台に分かれうること、WebSocket が最長60分で必ず切れること、常に1台起動しておくと C1（月500円）と C3（常時起動なし）を破ることが分かった。一方、今の構成は O2 のリハーサル（5部屋 × 50接続）で最大 82 ms、1回の本番で無料枠の1%未満で（[o2-rehearsal.md](../rehearsal/o2-rehearsal.md)）、性能を理由に移る必要はない。移る本当の価値は Go・GCP・Terraform を学ぶことにあるので、それと本番の安定を比べ、段階計画を決め直す。

Cloud Run の仕様と料金は、2026-11-03 に公式ドキュメント（context7 経由を含む）で確かめた。

| 項目                                   | 公式に書かれていること                                                                                                                                                                                                                                                                                        |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| WebSocket                              | 要求の timeout に従い、最大60分（既定5分）。15分より長くするなら、つなぎ直しに耐える作りにするよう勧めている。つなぎ直したとき、同じインスタンスにつながる保証はない                                                                                                                                          |
| max-instances                          | 急な増加や保守のとき、短い時間だけ超えることがあり、通常の運用でも週に数回起きる。猶予は15分か要求の timeout まで。上限はリビジョンごとなので、デプロイの直後は前と後のリビジョンが同時に動く                                                                                                                 |
| 料金（東京 asia-northeast1 は Tier 1） | 要求課金: 処理中 $0.000024/vCPU秒・$0.0000025/GiB秒、min-instances で待っているあいだ $0.0000025/vCPU秒・$0.0000025/GiB秒、100万要求 $0.40。インスタンス課金: $0.000018/vCPU秒・$0.000002/GiB秒（起動から終了まで、最低1分）                                                                                  |
| 無料枠（月・請求先アカウントごと）     | 要求課金: 180,000 vCPU秒・360,000 GiB秒・200万要求。インスタンス課金: 240,000 vCPU秒・450,000 GiB秒。Tier 1 の料金で差し引く                                                                                                                                                                                  |
| `*.run.app`                            | 既定の URL は無効にできる（Terraform では `default_uri_disabled`）。外からロードバランサー経由だけで届くようにするには、ingress を `internal-and-cloud-load-balancing` にする（`internal` では外部のロードバランサーからも届かない）。転送ルールは最初の5つで $0.025/時間。IAM で拒否された要求は課金されない |
| 要求のログ                             | 自動で作られ、Cloud Run では止められない（Cloud Logging の除外だけ）。`requestUrl` にはクエリまで、`remoteIp` には接続元の IP が残る                                                                                                                                                                          |
| 同時に処理する要求の数                 | 1インスタンスあたり最大1,000。gcloud・Terraform で作ると既定は vCPU の数 × 80、コンソールで作ると80。WebSocket は1本ずつ処理中の要求として数えるので、max-instances 1 では、つながる本数がそのまま1台の同時実行数になる                                                                                       |
| Firestore の無料枠                     | 1日あたり読み取り5万・書き込み2万・削除2万、保存1 GiB（太平洋時間の0時に戻る）                                                                                                                                                                                                                                |
| Cloudflare Containers                  | Workers Paid（月 $5）でだけ使える                                                                                                                                                                                                                                                                             |

WebSocket は開いているあいだずっと処理中の要求なので、つながっている時間がそのまま処理中として課金される。

## Decision Drivers

- DD1 障害時の振る舞い: A1（本番の1〜2時間に止まらず、切れても自動でつなぎ直して続けられる）・A3（締切まで終わった得点を失わない）・SC2。デプロイ、インスタンスの入れ替え、接続の時間の上限で切れても、`resume` で元の画面と得点に戻れる。部屋の状態が2か所に分かれない
- DD2 安全: S1〜S4 と ADR 0006（同じ origin、CORS なし）の守りを、今と同じ強さで保てる。API へ直接届く入口を作らない。GitHub から戻る URL の `code`・`state` や秘密がログに残らない（[logs.md](../runbooks/logs.md#ログに残るもの残らないもの)）
- DD3 費用: C1（月500円以内）・C3（常時起動のサーバーなし）・C4（予算アラートと、すぐ止める手順）
- DD4 学び: Go・GCP・Terraform を自分の手で書いて学べ、業務で使う GCP に結びつく
- DD5 品質: ① O2 のリハーサルで P1（1秒以内）・P3（取りこぼしなし）・P4（締切から2秒以内）を満たし、E2E と契約テストが通る ② デプロイしなければ、本番中に「再接続中」が出ない（今と同じ）

## Considered Options

基盤（イベントのあと、本番の API をどこで動かすか）

- K1. Go を Cloud Run の1台構成で動かす（max-instances 1、min-instances 0、要求課金、東京）。画面は Cloudflare に残し、画面の Worker が `/api/*` を Cloud Run へ転送して、同じ origin を保つ
- K2. K1 を min-instances 1 にする（常に1台起動しておく）
- K3. 本番は Cloudflare（TypeScript + Durable Objects）に残し、Go・GCP・Terraform は別の場所で学ぶ
- K4. Go を Cloudflare Containers で動かす（部屋の DO の後ろにコンテナを置く）

K1・K2 の中で決めること

- 部屋の状態の置き場所: J1 メモリだけ / J2 Firestore を正本にし、メモリは控えにする / J3 Cloud SQL
- `*.run.app` の守り方: N1 既定の URL は開けたまま、画面の Worker が付ける秘密のヘッダーをアプリで確かめる / N2 IAM で、呼べるのを画面の Worker のサービスアカウントだけにする（Worker が ID トークンを付ける）/ N3 既定の URL を無効にし、ingress を `internal-and-cloud-load-balancing` にして、外部のロードバランサーだけを入口にする

K3 の中で決めること（学ぶ場所）

- L1. ズバクイの Go 版を、本番とは別の練習用の環境として、K1 の形（J2・N2）で Cloud Run と Terraform で建てる。同時実行数（`max_instance_request_concurrency`）は、1台で受ける WebSocket の本数より大きくする。契約テスト（#149〜#151）で、今と同じ約束を守るかを確かめる
- L2. `tools/`（負荷テストのボットや契約テストのランナー）を Go で書き直す。GCP と Terraform は学ばない
- L3. ズバクイとは別のプロジェクトで学ぶ

## Decision Outcome

採用する選択肢: 「K3 + L1」。本番の API は Cloudflare（TypeScript + Durable Objects）に残す。Go 版はイベントのあとに書き、本番とは別の練習用の環境として Cloud Run と Terraform で建て、契約テストで確かめる。本番を Go 版に切り替えるかは、その結果を見て別の ADR で決め直す。

K1 と K3 を、同じ見方で比べた（K1 は J2・N2 を組み合わせたとき）。

|                                               | K1 Cloud Run の1台構成                                                                                                                                                                    | K3 Cloudflare に残す                                                                                                                                                                                                                                                                                                                                                           |
| --------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 部屋の状態の置き場所                          | Firestore を正本にし、メモリは控え（J2）。メモリだけ（J1）では、インスタンスが入れ替わると消える                                                                                          | 部屋ごとの DO の SQLite。DO は世界に1つ                                                                                                                                                                                                                                                                                                                                        |
| 2台に分かれたとき                             | max-instances の超過（週に数回）とデプロイの直後に起きうる。1人1回は Firestore のトランザクションで守れるが、別のインスタンスにつながった人へ送る仕組み（Firestore のリスナーなど）が要る | 起きない                                                                                                                                                                                                                                                                                                                                                                       |
| 60分の上限                                    | 全員が1時間に1回は切れ、`resume` に頼る。そのたび「再接続中」が出る。隠すには、画面が問題の合間に先回りしてつなぎ直す変更が要る                                                           | 上限なし                                                                                                                                                                                                                                                                                                                                                                       |
| デプロイで全接続が切れたとき                  | 前のリビジョンの接続は timeout まで残り、新しい接続は新しいリビジョンへ行くので、そのあいだ部屋が2つに分かれる。J2 なら `resume` で戻れるが、本番中はデプロイしない決まりが要る           | 眠っていた DO は、接続を保ったまま新しいコードに替わる。起きている DO は、既定（`code_update_strategy` が `deferred`、`max_delay` 300秒）では最大5分まで前のコードで動き、それまでに眠らなければ再起動して接続が切れる（2026-11-03 に Cloudflare の文書で確かめた）。切れても `resume` で戻れる（リハーサルで、切れた接続が戻ることを確かめた）。本番中は API をデプロイしない |
| 落ちたとき                                    | 新しいインスタンスに `resume` でつなぎ直し、Firestore から部屋を読み直す。メモリだけなら得点が消える                                                                                      | DO が再起動し、`resume` で戻れる（`resume.test.ts`・`player-reconnect.spec.ts`）                                                                                                                                                                                                                                                                                               |
| 月の費用（1 vCPU・512 MiB、30日、1ドル150円） | min 0: 本番とリハーサルは無料枠の中（1 vCPU なら月50時間まで）。min 1: 要求課金で約 $4.5（約680円）、インスタンス課金で約 $44（約6,600円）                                                | 0円（1回の本番で無料枠の1%未満。超えても課金されずに止まる）                                                                                                                                                                                                                                                                                                                   |
| 止める手順（C4）                              | 請求先アカウントが要る。予算アラートは知らせるだけなので、止めるには Pub/Sub と関数で課金を外す仕組みが要る                                                                               | Worker を消す。無料プランは課金されない                                                                                                                                                                                                                                                                                                                                        |
| `*.run.app` の守り方                          | IAM で、呼べるのを画面の Worker だけにする（N2）。Worker に GCP のサービスアカウントの鍵という新しい秘密が増える                                                                          | 直接届く入口がない                                                                                                                                                                                                                                                                                                                                                             |

| 学び（DD4）                                   | Go・Cloud Run・Terraform・Firestore・IAM を本番で学べる                                                                                                                                   | L1 なら、本番の運用のほかは同じものを学べる                                                                                                                                                                                                                                                                                                                                    |
| 品質（DD5）                                   | 数字は Cloud Run でリハーサルするまで分からない。60分ごとに「再接続中」が出る                                                                                                             | 最大 82 ms（リハーサルで実測）。デプロイしなければ「再接続中」は出ない                                                                                                                                                                                                                                                                                                         |

理由:

- DD1・DD2・DD3・DD5 のすべてで K3 が上回った。K1 の弱点は、どれも Cloud Run が短い要求を使い捨てのインスタンスで処理する基盤であることから来る。60分の上限も max-instances の超過も、長く生きる部屋とは相性が悪い。DO が基盤として保証していること（部屋は1つ、デプロイしなければ切れない）を、自分のコードと Firestore で作り直すことになる
- K1 が上回るのは DD4（学び）だけで、その大半は L1 で取り戻せる。L1 で失うのは、本番を運用する経験だけになる
- L1 なら、K1 の不安（60分ごとの切断、2台に分かれたとき）を、本番に触らずに Cloud Run の上で実際に確かめられる。契約テストはサーバーを問わずに作る（#145）ので、同じテストを今の TypeScript 版（`e2e:serve`。ログインにテスト専用の `/api/e2e/login` を使うので、本物の本番には向けない）と Go 版の両方に向けられる
- L2 は GCP と Terraform を学べず、L3 はズバクイの WebSocket と部屋という題材から離れるため、L1 を選んだ

比べて外した選択肢:

- K2 は、要求課金でも月約680円で C1 を超え、常に起動しているので C3 も破る。60分の上限と max-instances の超過は K1 と変わらない
- K4 は、Workers Paid の月 $5（約750円）が固定でかかり C1 を超える。部屋の正本は DO のままで、GCP と Terraform も学べない
- J1 は、インスタンスの入れ替え（こちらでは止められない）で部屋と得点が消え、A3 を破る
- J3 は、Cloud SQL のインスタンスが起動しているあいだ料金がかかり、C3 を破る
- N3 は、ロードバランサーの転送ルールだけで月約 $18（約2,700円）かかり、C1 を超える。N1 は、アプリまで届いた要求を確かめる守りで、届いた要求は課金される

## Consequences

- 良い影響: 本番の構成と運用は変わらない。部屋は DO に1つで、デプロイしなければ切れず、無料プランのまま C1・C3 を満たす
- 良い影響: Go・Cloud Run・Terraform・Firestore を、本番を壊す心配なく学べる。Go 版が今と同じ約束を守るかを、契約テストという外の基準で確かめられる
- 悪い影響: 本番で Go を運用する経験は得られない。本番のバックエンドは TypeScript のまま、DO 専用の API（Hibernation・DO の SQLite）に頼り続ける
- 悪い影響: 練習用の環境のために GCP の請求先アカウントを用意する。無料枠に収まる見込みでも、課金されうる構成になる（C4）
- 対応事項: 契約テスト（#147〜#151）を先に仕上げる。Go 版の目標は「契約テストがすべて通る」にする
- 対応事項: 練習用の環境は、本番と別の GCP プロジェクトに Terraform で建てる。min-instances は 0 にし、予算アラートを付け、すぐ消す手順を書く。本番の利用者とデータはつながない
- 対応事項: 本番を Go 版へ切り替えるかを別の ADR で決め直すのは、練習用の環境で次をすべて確かめたあと。① 契約テストがすべて通る ② Cloud Run の上で O2 のリハーサル（ホストを含めて255本の WebSocket）を行い、P1・P3・P4 を満たす ③ 60分の上限で切れても、画面に「再接続中」を出さずに続けられる方法がある ④ 2台に分かれても、1人1回（S4）と全員への配信（P1）が崩れない ⑤ C1・C3 に収まる
- 対応事項: イベントのあとにこの ADR を accepted にする。そのとき、ADR 0001 の「Go + Cloud Run へ置き換える」をこの ADR で置き換えたと書き、ADR 0005（Terraform を入れる時期）、`CLAUDE.md`、`docs/architecture/backend.md`・`operations.md` の「Go へ移す」の書き方を直す
