# 409・502 を返すルートができても、HTTP API は ADR 0011 の形（H1）を保つ

## Status

accepted

## Context

[ADR 0011](0011-hono-api-contract.md) で、HTTP API は Hono のルートと、`fetch` + protocol の zod で呼ぶ今の形（H1）を保つと決めた。あわせて、次のどちらかが起きたら、`@hono/zod-openapi` へ移るか（H3）を別の ADR で決め直すとした。

1. ルートの状態と `openapi.json` のずれが、CI を抜けて E2E・契約テスト・本番で初めて見つかった
2. ハンドラーが 200・201・204・404 のほかの状態（409・422 など）を返すルートができた

[ADR 0013](0013-host-admin-role.md) で、管理者がホストを足し・外す API を作ることにした。これが2つめに当たる。この ADR はそれに答える。1つめは起きていない。足すルートと状態は次のとおり。

| 経路                                     | 状態                              | 新しく返すところ                                                                                  |
| ---------------------------------------- | --------------------------------- | ------------------------------------------------------------------------------------------------- |
| `GET /api/me`                            | 200・401                          | なし                                                                                              |
| `GET /api/admin/hosts`                   | 200・401・403                     | 403 `forbidden`（`requireAdmin`、ミドルウェア）                                                   |
| `POST /api/admin/hosts`                  | 201・400・401・403・404・409・502 | 409 `already_exists` と 502 `github_unavailable`（ハンドラー）、403 `forbidden`（`requireAdmin`） |
| `DELETE /api/admin/hosts/{githubUserId}` | 204・401・403・404・409           | 409 `admin_host`（ハンドラー）、403 `forbidden`（`requireAdmin`）                                 |

ADR 0011 のあと、次のことが変わった。

- #240 で、ルートと `openapi.json` の経路とメソッドを両方向に突き合わせるテスト（`apps/api/test/openapi-routes.test.ts`）ができた。経路とメソッドのずれは CI で見つかる
- `openapi.json` に載るルートは、6本から10本になる
- 契約テスト（`tools/contract`）の `validateResponse` は、`openapi.json` に書いていない状態や content-type をエラーにする。ただし、サーバーが要るので、`CONTRACT_ORIGIN` を付けて手元で動かすだけで、CI では動いていない

## Decision Drivers

ADR 0011 の DD1〜DD5 を、そのまま使う。同じものさしで比べ直すため。

- DD1 ずれの検出: ルートの経路・メソッド・状態を変えたとき、`openapi.json` や画面の呼び出しとのずれが CI で見つかる
- DD2 基盤からの切り離し: 画面は Hono にも `apps/api` の型にも頼らない。Go 版へ向けても、画面と契約テストを変えずに済む（ADR 0001 の D5・D6、ADR 0008）
- DD3 本番に入るもの: 本番の API の Worker に、仕様を配る経路や Swagger UI を入れない
- DD4 変更の量: ルート・今のテスト・`openapi.json` の書き直しが小さい。同じ役割の仕組みを2つ持たない
- DD5 型のつながり: 画面が呼ぶ経路・本文・応答の型が、`tsc` の段階でサーバーとずれない

## Considered Options

- H1. 今の形を保つ。状態は `openapi.test.ts` の手で直す表で持ち、新しいルートの行を足す
- H5. H1 に加えて、契約テストを CI の `e2e` の job で `e2e:serve` に向けて動かす。テストで通した場面では、状態のずれも CI で見つかる
- H3. `@hono/zod-openapi` へ移り、ハンドラーが返す状態を `createRoute` から `openapi.json` に出す

ADR 0011 の H2・H4（画面が `hc` で呼ぶ）は、DD2 を満たさないとした理由が今回も変わらないので、比べる候補に入れない。

## Decision Outcome

採用する選択肢: 「H1」。今の形を保ち、新しい状態は `openapi.test.ts` の表とルートのテストで持つ。

|                        | H1 今の形                                                                                                                       | H5 H1 ＋ 契約テストを CI で                                                                                                                                             | H3 zod-openapi                                                                                                                                     |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| DD1 ずれの検出         | 経路とメソッドは #240 で見つかる。409・502 は、ルートのテストと `openapi.test.ts` の表の両方に書くが、その2つをつなぐものはない | テストで通した場面では、`openapi.json` にない状態が返ると落ちる。「書いてあるのに返さない」は見つからない。GitHub の 502 は stub を使えないので、契約テストでは出せない | ハンドラーの 409・502 と、POST の 404 は `tsc` でつながる。`requireAdmin` の 403・401・400・`csrf()` の 403 はミドルウェアが返すので、手書きのまま |
| DD2 基盤からの切り離し | 変わらない                                                                                                                      | 変わらない。同じテストを Go 版にも向けられる                                                                                                                            | 変わらない                                                                                                                                         |
| DD3 本番に入るもの     | 変わらない                                                                                                                      | 変わらない（`e2e` の job と `test/e2e-entry.ts` の中だけ）                                                                                                              | `OpenAPIHono` と zod-to-openapi が本番の Worker に入る                                                                                             |
| DD4 変更の量           | 表に4ルート分の行を足す                                                                                                         | `e2e` の job に、`e2e:serve` を後ろで立てて契約テストを流す手順と、管理者のシナリオを足す                                                                               | 10本と `jsonBody` を書き直し、`openapi.json` の作り手が替わる                                                                                      |
| DD5 型のつながり       | 変わらない                                                                                                                      | 変わらない                                                                                                                                                              | 変わらない（画面は `fetch` のまま）                                                                                                                |

理由:

- H3 が H1 より多く防げるのは、ハンドラーが返す 409・502 と POST の 404 のずれだけだった。新しい 403（`requireAdmin`）はミドルウェアが返すので、H3 でも手で書く。その差のために、10本の書き直し、`openapi.json` の作り手の交代、本番の Worker への依存の追加を払うのは見合わない（DD3・DD4）。ADR 0011 と同じ結論になる
- H5 は、状態のずれのうち「返したのに書いていない」を、テストで通した場面で CI で見つけられる。ただ、502 は契約テストでは出せず、`e2e` の job の手順と管理者のシナリオを足す手間に対して、捕まえられる範囲が狭い（DD4）
- H1 で、ルートは10本、状態は1本あたり多くて7つ。表の手直しは、目で追える量にとどまる。ルートのテストで表のすべての状態を1回は返させれば、ハンドラーが返す状態と表の両方が、同じ PR の中で目に入る

## Consequences

- 良い影響: 画面・本番の Worker・`openapi.json` の作り方は変わらない。ADR 0013 の API は、今の書き方のまま足せる
- 悪い影響: ハンドラーが返す 409・502 と `openapi.json` のずれは、これまでどおり CI では見つからない。手で直す `openapi.test.ts` の表と、ルートのテストと、手元で動かす契約テストに頼る
- 悪い影響: 状態は同じ 403 でも、`csrf()` のテキストと `requireAdmin` の `forbidden` の JSON の2つの形が並ぶ。`openapi.json` の 403 には両方を書く。400 の `BadRequest` と同じ書き方で、契約テストは content-type で見分ける
- 対応事項（#291・#292）: `openapi.ts` に新しい経路を書き、`openapi.test.ts` の状態の表に行を足す。管理者向けの経路の 403 は、`forbidden` の JSON と `csrf()` のテキストの両方を書く。ルートのテストでは、表に書いたすべての状態を1回は返させる（502 は GitHub の stub で）
- 対応事項: 見直しの合図を、次のように書き直す。どれかが起きたら、H3 へ移るかを別の ADR で決め直す。① ルートの状態と `openapi.json` のずれが、CI を抜けて E2E・契約テスト・本番で初めて見つかった ② ハンドラーが 200・201・204・404・409・502 のほかの状態を返すルートができた ③ `openapi.json` に載るルートが20本を超えた（表を目で追える量の目安）
- 対応事項: Go 版と比べるために契約テストを CI で動かす理由が別にできたら、そのときに H5 を考え直す
- 対応事項: ADR 0011 の見直しの合図の対応事項に、この ADR を指す一言を足す（ADR 0011 の Status は accepted のまま）。docs/README.md の一覧と、CLAUDE.md の ADR の範囲を直す
